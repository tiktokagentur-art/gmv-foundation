## Contracts

The four strict Pydantic models in app/management/schemas.py are authoritative for Python-side validation. The JSON document at api/schemas/management-v1.schema.json defines a transport envelope only; it is not a substitute for payload validation. All fixture IDs and employee references are synthetic.

Manager organizational status never confers technical authority. The offline policy requires an active, reviewed, technically verified profile, a verified unblocked technical identity, a matching employee ID, current mandate version, and an explicit scope. Unknown scopes fail closed. Self-approval is denied by can_approve. These predicates are not a replacement for an identity provider or Control Plane authorization.

## Ports and mocks
